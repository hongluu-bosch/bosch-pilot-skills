# Configuration Reference

Full layout of `config/project.json` plus the skill's directory tree.
Read this when retargeting a customer / product / base_dir, or
interpreting a path template placeholder.

> The Pydantic `schema_version` validator only accepts the current
> value; any other string hard-fails at load with a pointer at
> `--init-project`. Operators upgrading from a pre-release shape
> regenerate via `pipeline.py --init-project` and hand-copy custom
> `paths.*` values across.

> **For the operator workflow** (one-command `--init-project` to
> scaffold a workspace, interactive vs non-TTY behaviour, Bosch-tree
> auto-detection rules) see [`workspace-model.md`](workspace-model.md).
> This file is the schema reference.

## Project Structure

```
did-toolkit/
├── config/
│   └── project.json            # Project configuration (generated by --init-project)
├── inputs/
│   └── *.xlsx | *_did.json     # Diagnostic questionnaires (filename project-specific;
│                               # multi-candidate triggers --list-inputs flow)
├── outputs/                    # Reports + Phase 1 artefacts (project tree gets source)
│   ├── fscs/                   # Phase 1: fscs.json (authoritative) + fscs_edit.xlsx
│   ├── arxml/                  # Phase 2: validation + review reports only (ARXML lives in Bosch tree)
│   ├── implementation/         # Phase 3: generation + review reports only (.c/.h/PDM live in Bosch tree)
│   └── doors/                  # Phase 4 (opt-in): doors_upload_*.xlsx + doors_export.json
├── state/                      # Phase 4 only: doors_upload_state.json
└── scripts/                    # Operator-written extract_<customer>.py adapters
```

The skill installation lives elsewhere and contributes:

```
<skill-install>/scripts/
├── pipeline.py                     # Sole CLI entry point (incl. --init-project)
├── init_project.py                 # Workspace scaffolder (called by pipeline.py)
├── generate_arxml.py               # Phase 2 (import-only)
├── generate_implementation.py      # Phase 3 import shim (re-exports from implementation/)
├── generate_fscs.py                # Phase 1
├── implementation/                 # Phase 3 split package
├── fscs/                           # Phase 1 schema + adapter + xlsx edit + drift
│   └── doors/                      # Phase 4 DOORS pipeline
├── config/                         # Pydantic ProjectConfig schema + loader
├── review_fscs.py / review_arxml.py / review_impl.py
├── templating.py                   # Jinja2 environment factory
├── requirements.txt                # Runtime deps (Jinja2 + pydantic + openpyxl)
└── templates/                      # Jinja2 templates (impl + arxml)
```

Phase 2/3 write generated source directly into the Bosch project
tree (skip-on-conflict); no local source mirror, no rolling
backups.

## `config/project.json` (schema 2.2)

Generated by `python scripts/pipeline.py --init-project`. **Hand-edit
to retarget** a different customer / product / base_dir; re-running
`--init-project` on an already-initialised workspace auto-chains
into Phase 1 (with an optional Bosch-tree drift WARN — see
[`workspace-model.md`](workspace-model.md)).

> **Pre-release skill — strict schema pin, no migration shims.**
> The Pydantic `schema_version` validator only accepts the current
> string (`"2.2"`). Any other value (`"2.1"`, `"2.0"`, `"1.1"`, ...)
> hard-fails with a `ValidationError` pointing at `--init-project`.
> The `options` block is empty by design but kept with
> `extra='forbid'`, so any stale `options.*` key from an older
> schema (`output_mode`, `backup_before_write`, `backup_keep`,
> `overwrite_existing`, `generate_comments`,
> `validate_before_generate`, ...) hard-fails via `extra_forbidden`.
> Likewise for the culled top-level / `paths` fields (`project.*`,
> `product_type_mapping`, `paths.project_root`). Operators on an
> older shape regenerate `config/project.json` from scratch and
> hand-copy custom values across — no in-place upgrade.

### Schema example

```jsonc
{
  "schema_version": "2.2",

  "paths": {
    // Anchor for all relative paths below. Phase 2/3 resolve every
    // project-tree target as ``<base_dir>/<paths.*>``. Use an absolute
    // path for cross-shell stability; a relative one is resolved
    // from the active workspace root.
    "base_dir": "/abs/path/to/my-bosch-project",

    // Phase 3 project-tree targets (Phase 3 hard-aborts if base_dir
    // is missing — there is no fallback sink).
    "pdm_file":          "Fe_Super/rb/as/rbcn/core/app/dcom/RBAPLCust/cfg/RBDCOM_Customer.pdm",
    "config_h":          "Fe_Super/rb/as/rbcn/core/app/dcom/RBAPLCust/api/RBAPLCUST_Config.h",
    "config_elements_h": "Fe_Super/rb/as/rbcn/core/app/dcom/RBAPLCust/api/RBAPLCUST_ConfigElements.h",
    "config_settings_h": "Fe_Super/rb/as/rbcn/{product_type_lower}/dcompr/cfg/RBDCOM_ConfigSettings.h",
    "c_output_subdir":   "Fe_Super/rb/as/rbcn/core/app/dcom/RBAPLCust/src/{product_type_upper}",

    // Phase 2 project-tree target.
    "arxml_file":        "Fe_Super/rb/as/rbcn/core/app/dcom/RBAPLCust/cfg/{product_type_upper}/Dcm_CusDiag_Services_EcucValues_{product_type_suffix}.arxml",

    // Basename of the Phase 1 input recorded by --init-project.
    // Empty (the no-args default) until the QUESTIONNAIRE_READY
    // transition picks one. The COMPLETE-state auto-chain reads
    // this and feeds it to PipelineController.run_phase1 without
    // re-prompting. Hand-edit to swap questionnaires between runs.
    "input_did_json": "acme_did.json",

    // Per-product Bosch-tree overrides + skip sentinel.
    // Outer keys: canonical PT (DPB / ESP / ESPCL / IPB / RBU / Common).
    // Inner keys: any of the 6 path fields above.
    // Inner values: ``null`` (skip the Bosch write for this (PT, key))
    //   or non-empty string (literal override path used in place of
    //   template + placeholder expansion).
    // Auto-populated by --init-project from a live tree scan.
    "per_product": {
      "ESPCL":  { "arxml_file":        null },                                  // tree never has cfg/ESPCL/
      "Common": { "config_settings_h": null },                                  // tree never has Common/dcompr/
      "IPB":    { "config_settings_h": "Fe_Super/rb/as/rbcn/ipb/dcompr/cfg/RBDCOM_ConfigSettings_IPB.h" }
    }
  },

  // options is an empty placeholder kept with extra='forbid'
  // so stale knobs from older schemas fail loud at load.
  "options": {}
}
```

### Top-level fields

| Path | Type | Meaning |
|---|---|---|
| `schema_version` | string | Always `"2.2"`. Any other value hard-fails with a pointer at `--init-project`. |
| `paths` | object | All Phase 2/3 project-tree targets, plus the optional `per_product` override block. Strict — unknown keys raise `extra_forbidden`. |
| `options` | object | Empty placeholder. Kept with `extra='forbid'` so stale knobs (`output_mode`, `backup_before_write`, `backup_keep`, `overwrite_existing`, `generate_comments`, `validate_before_generate`, …) fail loud at load. |

### `paths.*` reference

| Field | Required | Used by | Meaning |
|---|---|---|---|
| `base_dir` | **required for Phase 2/3** | Phase 2 / Phase 3 / Phase 4 state file | Anchor for every other `paths.*` value. Points at the **project container** (the directory hosting the Bosch `rb/as/...` tree — i.e. the parent of `.DCOM_AI/`), **not** at the `.DCOM_AI/` workspace itself, so project-tree templates like `Fe_Super/rb/as/.../...pdm` resolve to `<container>/Fe_Super/rb/as/.../...pdm`. Absolute is safest; a relative path is resolved against the active workspace dir. NEVER points at the skill root. **Phase 2 / Phase 3 hard-abort (exit 2) if `base_dir` is empty or doesn't exist on disk** — the project tree is the sole sink, so a missing tree means nothing to do. |
| `pdm_file` | yes (when set) | Phase 3 | Bosch-tree PDM file. Phase 3 appends new DID entries; existing keys preserved (skip-on-conflict). |
| `config_h` | yes (when set) | Phase 3 | Bosch-tree `RBAPLCUST_Config.h`. Phase 3 merges new `#define`s; existing macros preserved. |
| `config_elements_h` | yes (when set) | Phase 3 | Bosch-tree `RBAPLCUST_ConfigElements.h`. Same skip-on-conflict semantics. |
| `config_settings_h` | yes (when set) | Phase 3 | Bosch-tree `RBDCOM_ConfigSettings.h`. Carries `{product_type_lower}` placeholder so one config drives every product. |
| `c_output_subdir` | yes (when set) | Phase 3 | Directory into which new `RBAPLCUST_*.c` files are **created** — existing files are never overwritten (skip-if-exists at the file level). Carries `{product_type_upper}` placeholder. |
| `input_did_json` | optional (defaults `""`) | `--init-project` COMPLETE state | Basename of the questionnaire chosen at the QUESTIONNAIRE_READY transition. Empty `""` means "no questionnaire recorded yet" (workspace was never advanced past FOLDERS_ONLY, or the field was hand-cleared). The COMPLETE-state branch auto-feeds this filename to Phase 1; pass `--input <basename>` on the CLI to override for a single run. |
| `arxml_file` | yes (when set) | Phase 2 | Bosch-tree ARXML file the per-product generation is merged into (deduplicated by `SHORT-NAME` under `DcmDsp/SUB-CONTAINERS`). Carries `{product_type_upper}` in the directory segment and `{product_type_suffix}` in the filename (routes the `Common` slot to `_SingleCANID.arxml`). |

**Empty-string semantics.** Any `paths.*` value left as `""` (the
`--init-project` default when no Bosch tree was detected) disables that
specific artefact. Phase 2 / Phase 3 still attempt the rest of the
work-set; the empty-string slots are logged as `[SKIP] <key> empty`.

### `paths.*` placeholders

`config_settings_h` / `c_output_subdir` / `arxml_file` carry
product-type placeholders that the runtime resolver
(`scripts/implementation/paths.py::resolve_path`) substitutes
**once per product** in each Phase 2 / Phase 3 fan-out iteration.
The build target is not a CLI flag — it is the work-set computed
from `outputs/fscs/fscs.json` (see
[`phase-2-arxml.md`](phase-2-arxml.md) §3 and
`scripts/fscs/product_workset.py`).

| Placeholder | Substituted with (production products) | Substituted with (`Common` slot) | Source |
|---|---|---|---|
| `{product_type_upper}` | Iteration's product, upper-case (`DPB`, `ESPCL`, …) | Title-case literal `Common` (so the resolved directory is `Common/`, not `COMMON/`) | `implementation/paths.py::product_type_upper` |
| `{product_type_lower}` | Hard-coded canonical lower-case tag — `ESP→esp10`, `DPB→dpb`, `ESPCL→esp10cl`, `IPB→ipb`, `RBU→rbu` | Title-case literal `Common` | `implementation/paths.py::product_type_lower` + `_DEFAULT_PRODUCT_TYPE_MAP` |
| `{product_type}` | Alias of `{product_type_lower}` | Same as `{product_type_lower}` (`Common`) | same |
| `{product_type_suffix}` | Same as `{product_type_upper}` (`DPB`, `ESPCL`, …) | Bosch-canonical literal `SingleCANID` | `implementation/paths.py::product_type_suffix` |

`{product_type_suffix}` exists solely so the cross-product
`Common` slot lands at the canonical Bosch ARXML filename
`Dcm_CusDiag_Services_EcucValues_SingleCANID.arxml` instead of
the nonsensical `_Common.arxml` that the legacy
`{product_type_upper}` substitution produced. The default
`paths.arxml_file` template generated by `--init-project` ends in
`Dcm_CusDiag_Services_EcucValues_{product_type_suffix}.arxml`;
operators upgrading hand-edited templates should switch the
trailing placeholder accordingly (otherwise the `Common` slot's
mirror write goes to `_Common.arxml`).

The canonical five-product map (`_DEFAULT_PRODUCT_TYPE_MAP` in
`paths.py`) is the only source. Adding a sixth product is a
deliberate code edit, not a config change.

### `paths.per_product`

Optional. Lets each product opt out of (or override) any of the six
mirror paths individually, on top of the top-level template. The
runtime resolver
(`scripts/implementation/paths.py::resolve_mirror_path`) consults
this block **before** falling back to template + placeholder
expansion.

#### Schema

```jsonc
"per_product": {
  "<PT>": {                   // outer key: canonical PT name
    "<key>": null | "<path>"  // inner key: one of the 6 mirror fields;
                              // value: skip sentinel or override path
  },
  ...
}
```

| Slot | Allowed values | Validator |
|---|---|---|
| Outer key (PT) | `"DPB"` / `"ESP"` / `"ESPCL"` / `"IPB"` / `"RBU"` / `"Common"` (case-sensitive — `"common"` / `"DPC"` etc. raise `ValueError`) | `_RECOGNISED_PRODUCT_KEYS` in `scripts/config/schema.py` |
| Inner key | `"pdm_file"` / `"config_h"` / `"config_elements_h"` / `"config_settings_h"` / `"c_output_subdir"` / `"arxml_file"` (any other key raises `ValueError`) | `_PER_PRODUCT_PATH_KEYS` in `scripts/config/schema.py` |
| Inner value | `null` (skip), non-empty string (override), or **field absent** (template fallback). Empty string `""` raises a validation error — use `null` for skip. | `ProjectPaths.per_product` validator |

#### Three-value semantics

| Inner value | Phase 2 (`arxml_file`) | Phase 3 (`pdm_file` / `config_*` / `c_output_subdir`) | Resolver verdict |
|---|---|---|---|
| `null` | **Entire product iteration is skipped** — no Bosch ARXML is touched and the per-product report directory under `.DCOM_AI/DID_Toolkit_PRJ/outputs/arxml/<folder>/` is not created. Pipeline logs `[SKIP] <PT>: paths.per_product.<PT>.arxml_file = null`. | **Just that one artefact** is skipped for that product — no Bosch tree write happens. Other artefacts for the same product still flow. | `MirrorResolution.SKIP` |
| `"<path>"` (non-empty string) | Bosch write goes to the literal override path (`<base_dir>/<override>`) instead of expanding the template. Reports still land under `.DCOM_AI/DID_Toolkit_PRJ/outputs/arxml/<folder>/`. | Bosch write goes to the literal override path (`<base_dir>/<override>`) instead of expanding the template. | `MirrorResolution.OVERRIDE` |
| absent (key not present in the inner dict) | Top-level `paths.arxml_file` template is expanded with `{product_type_*}` placeholders for this PT. | Top-level `paths.<key>` template is expanded with `{product_type_*}` placeholders for this PT. | `MirrorResolution.TEMPLATE` |

Empty top-level template (`""`) plus missing `paths.base_dir` is
how a workspace ends up with **no mirror at all**. That is a hard
error for Phase 2/3 (`exit 2`) — there is no local fallback, so
an unset Bosch tree blocks the toolkit entirely. Run
`--init-project` against a real tree first.

#### `--init-project` auto-detection

`--init-project` walks the live Bosch tree (when one is detected) and
synthesises this block automatically. The detector emits three
prefix-tagged lines after the standard `[OK]` setup messages so the
operator can verify before saving:

| Tag | Meaning | Typical trigger |
|---|---|---|
| `[INFO]` | "Already auto-disabled, no action needed" — the path is missing from the tree, so the detector wrote `null`. | `cfg/ESPCL/` missing → `per_product.ESPCL.arxml_file = null`; `Common/dcompr/` missing → `per_product.Common.config_settings_h = null` |
| `[CONFIRM]` | "Auto-defaulted to a variant; please confirm or hand-edit." | IPB `RBDCOM_ConfigSettings.h` missing but `..._IPB.h` / `..._IPB4HAD.h` / `..._RoPPSub.h` present → defaults to `_IPB.h` and lists alternatives |
| `[FYI]` | "Tree contains an extra ARXML or `src/` subdir not in the standard template; if you want to mirror, add an override manually." | Extra `Common/Dcm_..._EcucValues.arxml` no-suffix; extra `IPB/Dcm_..._IPB11.arxml`; extra `src/IPB11/` or `src/XPB/` |

`[FYI]` lines never produce overrides on their own — the operator must
hand-edit `paths.per_product.<PT>.<key>` to opt in.

### `options.*` reference

The `options` block is an empty placeholder kept only so
`extra='forbid'` catches stale keys at load time. All previously
supported knobs were retired; the table below is the rejected-key
list (no current knobs replace them — the new semantics handle
each case by other means).

| Field | Replacement |
|---|---|
| `output_mode` | Project tree is the sole Phase 2/3 sink. No CLI flag either (`--output-mode` is rejected by argparse). |
| `backup_before_write` | Skip-on-conflict semantics never overwrite, so backups are unnecessary. |
| `backup_keep` | Same. |
| `overwrite_existing` | Legacy compat flag with no consumer. |
| `generate_comments` | Same. |
| `validate_before_generate` | Same. |

## Rejected legacy fields (do not re-introduce)

If you find any of these in a stale `project.json`, `--init-project`
will refuse to load it. Regenerate from scratch.

| Removed field | Reason |
|---|---|
| `project.name` | Never read by any phase. |
| `project.customer_name` | Used only at `--init-project` build time to materialise `paths.*` literal segments — the value is baked into the strings, not stored alongside. |
| `project.project_root` | Same — build-time input, not persisted. |
| `project.created_date` | Write-only telemetry. |
| `project.last_modified` | Write-only telemetry. |
| `product_type_mapping` | Five-product canonical map lives in `paths.py::_DEFAULT_PRODUCT_TYPE_MAP`; the runtime override was a footgun for typos that silently misrouted Phase 3 writes. |
| `paths.project_root` | Duplicated `project.project_root`; both unread. The literal segment still survives baked into every `paths.*` string. |
| `options.output_mode` | Project tree is the sole sink. |
| `options.backup_before_write` | Skip-on-conflict never overwrites. |
| `options.backup_keep` | Same. |
| `options.overwrite_existing` | Legacy compat flag with no consumer. |
| `options.generate_comments` | Same. |
| `options.validate_before_generate` | Same. |

The `{customer_name}` path placeholder is also rejected —
customer is baked literally into `paths.*` strings by
`--init-project`. A stale template carrying `{customer_name}`
survives verbatim into the resolved path so the breakage is
visible instead of silently resolving to `""`.
