Standalone Static Code Review Skill 简化流程图

这张页面用最简单的方式说明 standalone skill 的工作流。它的主要用途是直接评审代码， 按功能影响判断问题级别；已有 finding 和导出报告只是补充输入，不是前置条件。

五步流程

步骤 1

输入

优先输入带明确目标的局部代码片段或源文件。已有 finding 列表和导出报告也可以作为补充输入。

步骤 2

校验

结合真实代码和内置规则，判断问题是否真的成立，是否有足够证据支撑。

步骤 3

去重

如果多条 finding 指向同一个底层缺陷，只保留最具体、最可行动的一条。

步骤 4

分级

只有明确影响功能或运行时行为的问题，才保留为 major 或 critical。证据不足的问题不放进 confirmed findings。

步骤 5

输出

根据 prompt 入口不同，输出聊天复核结果，或者生成 Markdown 和 HTML 报告。

常见输入

  • 带明确问题的局部代码片段
  • 带清晰评审目标的源文件
  • 补充性的 finding 列表或导出报告

主要输出

  • Confirmed Findings
  • Open Questions
  • Suspected But Unconfirmed Issues

回归检查

  • 去重后是否只保留关键 finding
  • 非功能性问题是否被正确降级
  • 真正高风险问题是否还能升到 critical

这套 Skill 擅长什么

  1. 直接对代码做功能影响评审
  2. 按实际功能影响重新定级
  3. 去掉重复项和规则噪声
  4. 形成更可辩护的最终评审结果

这套 Skill 不是什么

  1. 不是确定性扫描器的替代品
  2. 不是第一轮扫全量问题的工具
  3. 不是单独的发布门禁
  4. 不是把推测性问题直接变成 confirmed defect 的理由
