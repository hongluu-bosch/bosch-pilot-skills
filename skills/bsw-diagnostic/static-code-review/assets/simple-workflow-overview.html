Standalone Static Code Review Skill Workflow

This page shows the simplified workflow of the standalone skill. The main use is direct code review with functional-impact classification, while finding lists and exported reports remain optional inputs for validation and follow-up review.

Simple Flow

Step 1

Input

Start with a focused code snippet or a source file with a clear review goal. Existing finding lists and exported reports are also supported when you want to validate earlier review output.

Step 2

Validate

Check each issue against the actual code and the bundled guidelines. Confirm whether the finding is real and supported by evidence.

Step 3

Deduplicate

If multiple findings describe the same underlying defect, keep only the most specific and actionable one.

Step 4

Classify

Keep only clearly behavior-impacting issues as major or critical. Move weak, contextual, or uncertain issues out of confirmed findings.

Step 5

Output

Produce either a chat review result or Markdown and HTML reports, depending on which prompt entry point is used.

Common Inputs

  • Focused code snippet with a review question
  • Source file with a clear review goal
  • Optional finding list or exported report

Main Outputs

  • Confirmed Findings
  • Open Questions
  • Suspected But Unconfirmed Issues

Regression Check

  • Deduplicate to one major
  • Downgrade non-functional issues
  • Escalate true critical defects

What This Skill Is Good At

  1. Reviewing code directly against bundled rules
  2. Reclassifying severity by actual functional impact
  3. Removing duplicates and noisy guideline-only items
  4. Creating a more defensible final review result

What This Skill Is Not

  1. Not a replacement for a deterministic scanner
  2. Not a first-pass "find everything" tool
  3. Not a release gate by itself
  4. Not a reason to keep speculative findings as confirmed defects
