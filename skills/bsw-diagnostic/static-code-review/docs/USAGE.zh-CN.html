Static Code Review 使用文档

本文档面向最终用户，说明如何用最短提示词和最少操作完成当前文件或函数的 review，并自动生成标准报告。

1. 你只需要记住什么

提示词

  • Static Code Review Current File.
  • Static Code Review Selected Function.
  • Static Code Review Function <函数名>.

VS Code 任务

  • Static Code Review Setup
  • Static Code Review Current File
  • Static Code Review Selected Function
对普通用户，默认推荐路径是：当前文件运行 Static Code Review Current File；函数级 review 先选中函数，再运行 Static Code Review Selected Function。这两条路径都比聊天触发更稳，不依赖 Cline 聊天侧的命令审批策略。
三句话理解这个方案：用户只需要触发审查；系统自动执行规则检查、AI 判断、结果融合和报告生成；脚本链路负责校验、回归和问题定位。
规则原理为双审融合：先做规则审查，再做 AI 独立审查，最后融合两轮结果并按功能影响确定严重级别。

2. 第一次使用

  1. 把整个 static-code-review 文件夹复制到你的项目根目录。
  2. 打开 static-code-review 文件夹，双击运行 review-install.cmd。
  3. 执行后，项目根目录会自动安装这套 review 所需的项目配置（.clinerules、.vscode/tasks.json），并在本机初始化兼容 Cline 客户端的 auto approve 状态。
  4. 当前默认正式路径是 API review（依赖 %USERPROFILE%/.static-code-review/config.json 中的 api.apiKey），不依赖网页聊天登录态；只有在你明确切换到网页自动化维护路径时，才需要额外确认网页聊天服务登录状态。

3. 审查当前打开的 .c 文件

步骤
  1. 在 VS Code 中打开当前要审查的 .c 文件。
  2. 运行 VS Code 任务：Static Code Review Current File

完成后会通过网页自动化直接写正式报告到 review-reports/，不依赖你手工保存一个新建编辑器文件。这里的“当前文件”指当前活动的源码文件，不是已经生成出来的报告 HTML 标签页。

4. 审查某个函数

推荐方式

  1. 先在编辑器中选中该函数。
  2. 运行 VS Code 任务：Static Code Review Selected Function

简化方式

  1. 在当前文件打开状态下，直接输入：Static Code Review Function <函数名>.
如果你追求最稳的函数级范围控制，优先使用“先选中函数，再运行 Static Code Review Selected Function 任务”。

5. 报告会生成到哪里

  • review-reports/static-code-review-report.current-file.<文件名或函数名>.<时间戳>.html
  • review-reports/static-code-review-report.current-file.<文件名或函数名>.<时间戳>.zh-CN.html

文件名始终包含正式报告前缀 static-code-review-report.current-file，中间拼接实际审查的文件名或函数名，末尾为时间戳。具体评审范围仍会写在报告标题和头部元信息里。正式输出以 HTML 为主；如果工作区里已有旧的 Markdown 报告，也会在归档时一并移动。

无论是当前文件、单函数还是选中函数，只要写入新的正式报告，系统都会先把 review-reports/ 根目录里现有的正式报告统一归档到 archive/。如果你想提前单独归档，也可以手动运行 Static Code Review Archive Current Reports。

6. 常见问题

  • 没有生成报告：先确认已经完成初始化，并且当前活动标签页是要审查的 .c 源码文件，而不是 review-reports/ 下的 HTML 报告，然后重新运行 Static Code Review Current File 任务。
  • 报告内容不完整：通常是导入的 Kimi 回复不完整，重新复制完整回复后再执行一次当前文件 review。
  • 报告已经过期：常见原因是源文件在报告生成后又被修改，重新触发一次当前文件 review 即可。
